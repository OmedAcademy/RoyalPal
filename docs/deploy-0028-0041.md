# Deploying migrations 0028 – 0041

Production is on `0027`. Fourteen migrations are outstanding.

**Nothing in this document has been run against production.** The ordering
claims below are derived from the repository and, where stated, verified
against a real Postgres with every migration applied (PGlite, the same harness
CI uses). The production database's actual state is unknown from here — **Admin
→ Diagnostics** probes it table by table and is the only authority on what is
already applied.

---

## The two rules

**1. Five migrations remove a permission the currently-deployed code uses.**
Apply one of those before its code is live and the feature does not degrade —
it breaks outright, for everyone, immediately.

| Migration | Removes                                                                         | Breaks if applied early                            |
| --------- | ------------------------------------------------------------------------------- | -------------------------------------------------- |
| `0028`    | Tutor writes to their own Stripe/commission columns                             | Tutor onboarding                                   |
| `0029`    | Client `INSERT` on `bookings`                                                   | All booking creation                               |
| `0030`    | Participant cancelling a **paid** lesson directly                               | All cancellation                                   |
| `0039`    | Signup without a `date_of_birth`                                                | Every new registration                             |
| `0041`    | `SELECT` on `profiles.phone` / `date_of_birth` and six `tutor_profiles` columns | **Every signed-in page and every `/api/v1` route** |

**`0041` is the most damaging of the five.** Before commit `bfcd54c`,
`requireProfile`, `requireProfileAllowingSuspended` and `requireApiUser` each
ran `from("profiles").select("*")`, and `select *` fails outright when the role
lacks any column. Verified: that exact statement returns `permission denied for
table profiles` against a database with `0041` applied, while the post-`bfcd54c`
column list succeeds on the same database.

**2. Nine migrations create objects the deployed code reads.**
They cannot break old code — but the new code needs them. Between the deploy
and these migrations, messaging, support, push registration, rescheduling and
the account-deletion screens all query tables that do not exist yet and return
errors. That is not a reason to reverse the order; it is a reason to keep the
window to minutes and to do it at a quiet hour.

**The safe sequence is therefore: deploy the code, confirm it is live, then
apply `0028` → `0041` in numeric order, in one sitting.**

---

## Pairs that cannot be separated

| Pair            | Why                                                                                                                                                                                                                                                                                                                                                                              |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `0038` + `0040` | `0038` creates `consume_rate_limit`, and Postgres grants `EXECUTE` on every new function to `PUBLIC`. Between the two, **any anonymous caller** can burn an arbitrary rate-limit bucket — the key is `<policy>:<sha256(identifier)[0:40]>`, unsalted, so a victim's login key is computable from their email address. **Never apply `0038` without `0040` in the same session.** |
| `0034` + `0040` | Same mechanism: `0034` grants `reschedule_booking` to `authenticated`, and `0040` revokes it. In between, any booking participant can bypass the three-move cap, the 24-hour notice rule and the open-slot check by calling the RPC directly.                                                                                                                                    |
| `0030` + `0037` | `0030`'s rewritten status trigger is what `0037`'s audit columns record the decisions of. Applying `0030` alone leaves cancellations happening with no policy recorded against them.                                                                                                                                                                                             |
| `0036` + `0039` | `0039` rewrites `handle_new_user` to write the columns `0036` adds. `0039` before `0036` fails immediately — the columns do not exist.                                                                                                                                                                                                                                           |
| `0008` + `0035` | Already applied / outstanding split: `0035` **redefines** the `recompute_tutor_rating` trigger `0008` created. It is not additive to it; it replaces it.                                                                                                                                                                                                                         |

Everything else is order-independent within the numeric sequence, but there is
no reason to split it.

---

## Per migration

Each verification query is read-only and should be run in the Supabase SQL
editor after applying that migration. Each rollback restores the previous
state; **`0036` and `0037` are the two that cannot be fully rolled back** —
dropping their columns destroys the data written into them.

### 0028 — lock the tutor platform columns

**Does:** adds `protect_tutor_platform_columns()` + trigger, so a tutor cannot
write their own `stripe_account_id`, `platform_fee_bps`, Connect state or
rating.
**Order:** **CODE FIRST.** `startTutorOnboarding` must already write through the
service role.

```sql
select tgname, tgenabled from pg_trigger
 where tgrelid = 'public.tutor_profiles'::regclass
   and tgname = 'protect_tutor_platform_columns';
-- expect 1 row, tgenabled = 'O'
```

```sql
-- rollback
drop trigger if exists protect_tutor_platform_columns on public.tutor_profiles;
drop function if exists public.protect_tutor_platform_columns();
```

### 0029 — booking integrity

**Does:** adds `protect_booking_columns()` and `enforce_booking_insert_invariants()`

- triggers; removes client `INSERT` on `bookings`; adds
  `reviews_insert_own_completed_paid_booking`.
  **Order:** **CODE FIRST.** `createBooking` must already insert through the
  service role.

```sql
select tgname from pg_trigger
 where tgrelid = 'public.bookings'::regclass
   and tgname in ('protect_booking_columns','enforce_booking_insert_invariants')
 order by tgname;
-- expect exactly 2 rows
select has_table_privilege('authenticated','public.bookings','INSERT') as can_insert;
-- expect false
```

```sql
-- rollback
drop trigger if exists protect_booking_columns on public.bookings;
drop trigger if exists enforce_booking_insert_invariants on public.bookings;
drop function if exists public.protect_booking_columns();
drop function if exists public.enforce_booking_insert_invariants();
grant insert on public.bookings to authenticated;
```

### 0030 — lock paid-booking cancellation

**Does:** rewrites `enforce_booking_status_transition()` so a participant cannot
cancel a paid lesson directly.
**Order:** **CODE FIRST.** `cancelBooking` must already write through the

```sql
select position('service_role' in pg_get_functiondef(p.oid)) > 0 as locked

```

### 0034 — rescheduling

**Does:** `booking_reschedules`, one index, one policy, `reschedule_booking()`

**Order:** additive — **but apply with `0040` in the same session**, or the RPC

```sql

  from pg_proc p join pg_namespace n on n.oid = p.pronamespace

```

### 0035 — review moderation

**Does:** hide/reply columns on `reviews`, redefines `recompute_tutor_rating()`,
adds `protect_review_columns()` + trigger, three policies, redefines the
`review_authors` view, one partial index.
**Order:** additive. Replaces a trigger `0008` created — not additive _to_ it.

```sql
select count(*) = 4 as cols from information_schema.columns
 where table_schema='public' and table_name='reviews'
   and column_name in ('hidden_at','hidden_by','hidden_reason','tutor_reply');
select position('hidden_at' in pg_get_functiondef(p.oid)) > 0 as excludes_hidden
  from pg_proc p join pg_namespace n on n.oid=p.pronamespace
 where n.nspname='public' and p.proname='recompute_tutor_rating';
-- expect both true
```

```sql
-- rollback (loses moderation history)
drop trigger if exists protect_review_columns on public.reviews;
drop function if exists public.protect_review_columns();
alter table public.reviews
  drop column if exists hidden_at, drop column if exists hidden_by,
  drop column if exists hidden_reason, drop column if exists tutor_reply,
  drop column if exists tutor_replied_at;
-- then re-run the 0008 recompute_tutor_rating definition
```

### 0040 — revoke public function grants

**Does:** revokes `EXECUTE` on `consume_rate_limit` and `reschedule_booking`
from `PUBLIC`, `anon` and `authenticated`.
**Order:** additive and safe at any point — **but must not lag `0034` or
`0038`**. No application code has ever called either function as a client.

```sql
select p.proname,
       has_function_privilege('anon', p.oid, 'EXECUTE') as anon,
       has_function_privilege('authenticated', p.oid, 'EXECUTE') as auth
  from pg_proc p join pg_namespace n on n.oid=p.pronamespace
 where n.nspname='public'
   and p.proname in ('consume_rate_limit','reschedule_booking');
-- expect both columns FALSE on both rows
```

```sql
-- rollback (reopens both holes — do not, except to unblock an incident)
grant execute on function public.consume_rate_limit(text, integer, integer) to authenticated;
grant execute on function public.reschedule_booking(uuid, timestamptz, text, integer) to authenticated;
```

### 0041 — restrict profile column exposure

**Does:** replaces table-level `SELECT` on `profiles` and `tutor_profiles` with
column-level grants. Withholds `phone` and `date_of_birth` from
`authenticated`; withholds `stripe_account_id`, `platform_fee_bps`,
`stripe_disabled_reason`, `stripe_requirements_due`, `stripe_payouts_enabled`
and `stripe_details_submitted`; leaves `anon` exactly `id` and
`verification_status` on `tutor_profiles`. No policy is altered.

**Order:** **CODE FIRST — commit `bfcd54c` or later must be live.** Verified:
the pre-`bfcd54c` `select *` returns `permission denied for table profiles`
against a database with this applied, which would break every signed-in page
and every `/api/v1` route at once.

```sql
select a.attname
  from pg_attribute a
 where a.attrelid = 'public.profiles'::regclass
   and a.attname in ('phone','date_of_birth')
   and has_column_privilege('authenticated', a.attrelid, a.attnum, 'SELECT');
-- expect ZERO rows

select a.attname
  from pg_attribute a
 where a.attrelid = 'public.tutor_profiles'::regclass
   and a.attnum > 0 and not a.attisdropped
   and has_column_privilege('anon', a.attrelid, a.attnum, 'SELECT')
 order by a.attname;
-- expect exactly: id, verification_status

select count(*) as profile_policies from pg_policies
 where schemaname='public' and tablename='profiles';
-- expect 5 — this migration must not have changed any policy
```

```sql
-- rollback (restores the exposure)
grant select on public.profiles to authenticated;
grant select on public.tutor_profiles to authenticated;
grant select on public.tutor_profiles to anon;
```
